Added

* **A changelog fragment can no longer claim work its diff did not do (issue #766).** In sprint 8 a fragment under Added claimed a flag and two functions the base already had, written from the plan's task titles, and QA approved it. The new Verifier check `changelog_matches_diff` (`backend/app/services/evidence/changelog_diff.py`) judges a delivery that writes a fragment against what the platform observed, recorded by `backend/app/services/loop/changelog_observe.py`: the daemon's diff of the delivery's commit against the merge base, the fragment at that commit and the cited files at the merge base. A cited path the diff did not change, a name under Added that the base already has, or an issue other than the one the sprint's objective names refutes, and the gate in the existing `backend/app/services/evidence/delivery_gate.py` sends the delivery back before QA. What cannot be compared is unverifiable and holds the task for a person (risk tier high). A writer's prompt gets the `changelog_diff` section (`backend/app/services/loop/worker/changelog_prompt.py`) telling it to call the existing workspace git tool's changed and diff operations first, and QA's review lists the check first and whole (`backend/app/services/loop/worker/review_evidence.py`). The PO's changelog task now depends on every other task of the sprint (`backend/app/services/planning/changelog_order.py`). `changelog.d/README.md` tells writers the rule. `backend/tests/test_changelog_matches_diff.py` replays sprint 8's fragment against its diff (refuted; the corrected text passes) and sprint 7's fragment for a nonexistent issue #780 (refuted).
