Fixed

* **An agent can run the project's own check scripts, never one it changed (issue #766).** `workspace__run_tests` with exactly `python3 scripts/<name>.py [args]` (or `python`) now runs that script at the project root, through the same `workspace.execute` request, sandbox and command policy as a test run, when the script is committed on the default branch and its bytes on disk are the committed ones (the backend hashes the committed bytes and compares them with the daemon's `workspace.hash`). Arguments take plain characters only: no shell operator, quote, variable, glob, `..` or absolute path. A script the task edited, moved or delivered over, one not committed, or any other command keeps the substitution by the folder's test command, and the reply says why. In sprint 6 a QA criterion asked for `scripts/check_file_sizes.py`, the tool could never run it, and QA tried to overwrite the script to make it runnable.
