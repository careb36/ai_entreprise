* **The audit trail in the web app (`docs/archive/design/FRONTEND_GAPS.md`, P1).** A new Audit trail page (`/company/audit-trail`, every member) asks the backend to walk the company's whole audit chain (`GET /v1/audit/chain`) and shows whether it is intact, its hash mode, the head row and hash to record outside the factory and, as an alert, each row where it breaks; and it takes the customer-key anchor end to end: the head's statement to copy (`GET /v1/audit/anchors/statement`), the documented `openssl` command, and the base64 signature pasted back (`POST /v1/audit/anchors/signature`; checked for shape before sending, verified only by the backend). A task's page gains its event log, read when opened (`GET /v1/tasks/{id}/events`: events in order with actor, status and run, the task chain's state, which record the board reads). Each anchor on the Audit anchors page downloads its receipt as JSON (`GET /v1/audit/anchors/{id}/export`). The browser computes no hash and judges no signature (`docs/POSITIONING.md`, rule 6).
