Added

* **Record tools and tool demand per sprint (issue #766).** Two read-only tools, `board__task` (a task's history: status moves, comments, attempts, rework requests, dependencies) and `board__evidence` (a run's Verifier checks, the delivered files with the sha256 the backend sent and the daemon read back, the tools it was offered, and the producer's claims), go beside the QA review's reads, the Architect's brief tools and an execution turn's tools on a rework (`BOARD_TOOLS_ENABLED`, on by default). The backend sets the scope, never the call: the turn's company, its task and the tasks it depends on; any other task is refused and the refusal is recorded. Each reply prints the platform's observations and the agents' and people's claims under separate headings, is redacted like a read and is cut to the result budget; each call is a read-only observation. `board` is now a reserved MCP server name. The retrospective adds the sprint's tool demand next to its other numbers, labelled as observations: unknown tool names asked, final answers that were a tool call written as text, refused calls (a fetch to a host not allowed, a `run_tests` command not run as asked, which is now recorded as `refused`, a check script that may not run, a record outside the scope) and runs that used up their tool rounds. All of it is counted from the platform's own records (`services/contracts/tool_demand.py`).
