Fixed

* **A delivery that changes code is no longer `verified` without a test observation (issue #766).** On 2026-11-20 the factory's own company held 66 verifications and none contained a test run: with `DELIVERY_TESTS_ENABLED` off the delivery recorded nothing, the Verifier added `tests_run` only when a `test_run` was present, and the verdict was computed over the checks present, so a missing check read as a pass. The Verifier now decides what a delivery requires before reading what ran (`services/evidence/required_checks.py`): a delivery that changes any path that is not documentation requires the platform's `tests_run` or an independent CI conclusion, and a required check that did not run is `unverifiable` with the reason. The delivery records why tests did not run (disabled for the deployment, or files not confirmed written), and each verification records the policy that produced its verdict (`verdict_policy`: version and required checks). Earlier verifications are not rewritten.
