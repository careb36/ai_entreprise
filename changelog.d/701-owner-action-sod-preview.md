* **The self-hosting owner action shows a segregation-of-duties blocker before it starts, and stops cleanly instead of failing at the approval (issue #701).** The run drafts and approves the specification and the architectures as the Owner, which the default `high_risk` mode refuses without the single-person exception. The preview of `self_host_container_run` now observes the policy of the company the run will use (the one an earlier run with the same checkout name created, else a new one) with `sod.decide`, and puts it in the facts its digest covers (`backend/app/services/management/owner_action_sod.py`). A reused company that would refuse is a `sod_refused` blocker: the start is a 409, and the confirmation dialog names the approvals, the mode and whether the exception is in force or could be granted, with a link to that company's policy (`/company/duties?company=N`). A new company is not a blocker: the run creates it and stops `blocked_by_sod` right after, before any approval or model call, and the run panel shows the next step (grant the exception, then run again with the same checkout name). The action never grants, changes or bypasses the policy.
