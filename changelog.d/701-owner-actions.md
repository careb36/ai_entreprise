* **Owner actions from the app, starting with the self-hosting run in container mode (issue #701).** A catalogue of steps only the company's Owner takes, each with typed parameters, a confirmation that shows its effect and cost (the start echoes the preview's digest), one run at a time, cancel, and start, cancel and finish in the company's audit chain (`GET /v1/owner_actions`, `POST /v1/owner_actions/{name}/preview`, `…/runs`, `…/runs/{id}`, `…/runs/{id}/cancel`; Owner only, never a Manager or an API token). The first action, `self_host_container_run`, runs the harness's `checkout, company, records, issue, wait, sandbox` steps with `--container-mode` without a token: the backend calls its own API in-process as the Owner (`InProcessPrincipal`), and the daemon makes the snapshot under its own root through the new `workspace.self_host.checkout` subject (a folder name, never a path). The run records the checkout, the company, sprint and agent run ids, the sandbox report (asked and observed apart) and the tokens observed, and stops the sprint when the token budget is passed. The inbox lists the actions for an Owner, and the Company menu has an Owner actions page. Design and threat model: `docs/design/owner-actions.md`.
