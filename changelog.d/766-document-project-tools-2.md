Added

* **More tools for documenting a whole project: the docs build, snippet names, and what the project declares (issue #766).** The stack profile gains `docs_build`, which a company may set and which is detected from `mkdocs.yml`, a Sphinx `conf.py` under `docs/` or `doc/`, or a `docusaurus.config.*` at the root, in `website/` or in `docs/` (the site is built into `/tmp`, never into the project). Where a turn may run commands, `workspace__docs_build` runs that command in the sandbox, with no argument, and returns the exit status and the first errors. For a delivery that writes documentation, the loop runs the same build through the daemon (`services/loop/docs_checks.py`), and the new Verifier check `docs_build` judges the run: exit 0 passes, another exit refutes and the gate sends the delivery back, a build that did not really run (missing builder, no sandbox, timed out, refused, tests off) is unverifiable, and a project with no build command gets no check, never a pass. The new check `docs_snippet_names` reads the delivered documents' fenced Python and JavaScript/TypeScript snippets for the project names they import (`from pkg import name`, `import { name } from './x'`) or call (`module.name(…)`), and looks each one up in the daemon's code graph, recording the files and sha256 it read. A name with no definition is a finding, not a refutation; names the daemon could not settle make the check unverifiable. Snippets are never run. Three read-only tools, offered wherever the read tools are and only when every daemon announces them, answer from a static reading on the daemon (`workspace.related` with `lookup.kind` `api_surface`, `config_vars` or `dependencies`, `vscode-daemon/project_facts.py` and `manifest_deps.py`, PROTOCOL.md §5.9). `workspace__api_surface` returns committed OpenAPI documents and FastAPI-style routes with file and line, starting no server. `workspace__config_vars` returns the environment variables the code reads, with literal defaults; it never reads a `.env` file and withholds a default whose name looks like a secret. `workspace__dependencies` returns the direct dependencies of `pyproject.toml`, `requirements*.txt` and `package.json` as declared; it never returns a direct reference's URL. Each call records the sha256 of every file a row came from. `research__package` now returns `license_by_registry`, the licence as the registry states it.
