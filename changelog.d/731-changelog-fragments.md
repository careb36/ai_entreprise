* **Changelog fragments: one file per change, collected at release (issue #731).** A pull request records its change as `changelog.d/<issue>-<slug>.md` (first line the Keep a Changelog section, the rest the entry) instead of writing into `CHANGELOG.md`, where every merge into `main` made every other open pull request conflict and restarted its checks. `python3 scripts/release_notes.py collect` folds the fragments into `[Unreleased]` under their sections, in section order and then by file name, deletes them, refuses an unknown section, an empty entry, a heading or a bad file name, and changes nothing when run twice; `release` (now also `cut`) collects first, so the release section holds the fragments. `unreleased` prints `[Unreleased]` with the fragments folded in, and `notes` for `[Unreleased]` (a pre-release's notes) reads them too. `scripts/check_changelog.py` checks every fragment and fails while `CONTRIBUTING.md` or the pull request template still asks for a `CHANGELOG.md` edit; it runs in `scripts/check.sh` (quick and full) and in the backend tests. The entries already under `[Unreleased]` stay where they are. Design after towncrier (news fragments) and changesets (one file per change); no code taken. Standards: Keep a Changelog 1.1.0; ISO/IEC 27001:2022 A.8.32.
