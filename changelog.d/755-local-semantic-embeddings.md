Changed

* **Memory embeds with a local semantic model by default (issue #755).** DeepSeek has no embeddings endpoint, so `EMBEDDING_PROVIDER=local` (the default) now runs `intfloat/multilingual-e5-small` (MIT, 118 MB int8 ONNX, multilingual: Spanish and English) on CPU in the LLM proxy with ONNX Runtime: no key, no outside call and no download at run time, nothing leaves the proxy (GDPR arts. 25 and 28). The model and its tokenizer are fetched at image build time from a pinned revision and checked against the sha256 in `llm-proxy/embedding_model.json` (a mismatch fails the build), checked again before loading, and must pass a self-check in both languages; when the model cannot load, the hash vector of #751 stands in and `capabilities.embeddings` is `degraded` with the reason. `EMBEDDING_PROVIDER=local-hash` chooses the hash vector on purpose. The 384 values are padded with zeros to the 1536 of `vector_memory.embedding`; each row now records its source in `vector_memory.embedding_model` (migration 0057, existing rows marked as the hash vector), a search compares only vectors of the same model, and the backend re-embeds the other rows at start once the semantic model answers. `/health/deep` shows `memory` on only when the embedding is semantic. The proxy image grows by about 370 MB uncompressed (about 100 MB compressed): the model and the runtime; each proxy worker holds about 400 MB more memory.
