Added

* **Change your password in the app, and an audited reset for a forgotten one (issue #766).** `POST /v1/auth/password` lets a signed-in person change their password: the current one is checked with bcrypt under the sign-in's per-account backoff (a lock answers 429, a wrong password 403 and changes nothing), the new one follows the existing `check_new_password` rule and must differ from the current one. Every session family of the person is revoked, this one included, and a browser session gets a new family in the answer's cookies. An API token or an owner action gets 403, and an account that signs in only with single sign-on is told it has no password (409). The change, the revocations and one `password_changed` audit row per company of the person (in each company's hash chain, with the user id and the sessions ended, never a password or hash) are one commit (`backend/app/services/platform/password_change.py`). `GET /v1/auth/me` now returns `has_password` and `password_min_length`, and the Account page gains a Password panel (current, new, repeat, with the minimum length shown). For a forgotten password, an operator on the server runs `docker exec -it factory-backend python -m reset_password` (`backend/app/reset_password.py`; `scripts/reset_password.py` only runs that command): it asks for the email and reads the new password twice with `getpass`, applies the same rule, ends every session and writes `password_reset_by_operator` through the audit path. Documented in `docs/OPERATIONS.md` ("A person forgot their password"), `SECURITY.md` and the threat model `docs/design/change-password.md`.
