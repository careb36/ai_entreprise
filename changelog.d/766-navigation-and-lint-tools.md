Added

* **Code navigation and lint on demand as agent tools (issue #766).** `workspace__definition` says where a function, class or method is defined (path, line, signature, and for a top-level Python one its parameters as `workspace.signatures` reads them, with the file's sha256 as the daemon read it); `workspace__references` lists the files and line numbers that use a name or what a module defines. Both are read-only, ask the daemon's existing code graph through an optional `lookup` field on `workspace.related` (no new NATS subject; `vscode-daemon/code_lookup.py`, PROTOCOL.md §5.7), are offered to every toolbox with the read tools (the file roles', the Architect's brief, QA's review) only when every daemon announces the `lookup` feature, and are bounded, redacted and limited to paths inside the project. `workspace__lint` runs the stack profile's lint (and type check, when a profile names one) narrowed to the given paths, through `workspace.execute` in the sandbox under the command policy and `EDIT_LINT_TIMEOUT_SECONDS`, never a command that rewrites files and never command text from the model; it is offered in execution turns only, when the profile names a lint command. Every call is an observation on the turn. From the design's next changes 6 and 7 (`docs/design/agent-toolsets.md`).
