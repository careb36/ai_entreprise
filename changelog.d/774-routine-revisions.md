* **A routine's revisions and variables (issue #774).** Each change that alters a routine is now a numbered revision holding the whole routine (`GET /v1/routines/{id}/revisions`), and a Manager can restore an earlier one, recorded as a new revision (`POST /v1/routines/{id}/revisions/{number}/restore`). A routine can declare variables (a default, required or not, allowed options) and use them as `{{name}}` in its description; "run now" accepts values, a scheduled run takes the defaults and is skipped, with the reason audited, when a required one is missing. Each run records the revision and the values it used, so a routine's sprint is attributed to the exact version it ran. Existing routines get their revision 1 (migration 0063).
