* **The Live page and the board show the records' statuses, not guesses from the event stream (issue #766).** A new `GET /v1/sprints/{id}/live_state` says who is working (a task run or a QA review in flight, only while the sprint runs), why a paused sprint is paused (`pause_kind`, also on the board), when a closed sprint closed, and each health tile from its record: agents with a run in flight, failed agent calls, blocked tasks, tasks with an unanswered rework request, the last event an agent recorded (no longer called a heartbeat), the workspace daemon's heartbeat and the previous sprint's tally. A completed, paused or cancelled sprint shows nobody working; a message group's badge shows its latest state (approved, rework requested, blocked, delivered) instead of its first event; authors resolve to the company's roles (the Verifier, the quality gate, a person and the system are not listed as agents, and no name shows as a generic "Agent"); events are placed by their own time, the ones after the close under "After the sprint closed", and an event without an id gets one so a reconnection does not show it twice. On the board, each card names what holds it back from its record (`observed.hold`: waits for a person, for tasks `#n`, a retry or review the worker runs itself, frozen, a risk hold, the run window); a task that only waits for another task no longer says it needs a person, and the paused banner says why and what to do in the person's language, with the recorded reason.
