* **Read-only git for the agents: `workspace__git` (issue #766).** The roles that read the project get one tool with a fixed set of operations and no free arguments: `status`, `changed` (the files this task changed against its base branch, committed or not), `diff` of one path against the base, `log` (at most 20 commits) and `show_base` (a path as the base branch has it). The first four are new views on the daemon's `workspace.git.diff` (`view`, PROTOCOL.md §5.6, announced as its `view` feature); `show_base` reuses `workspace.git.read_at`. Each operation is offered only when every daemon announces it. Paths stay inside the project and never name VCS metadata or a secret file; outputs are bounded and redacted; every call is recorded as a read-only observation. Real runs had Developers asking the test runner for `git status` and QA unable to tell which files to verify.
