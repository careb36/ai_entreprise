Fixed

* **The tool loop records why a call failed, how many rounds it used, and refuses a tool call written as text as a delivery (issue #766).** An audit of 108 runs (1,460 tool calls) found 25 of 28 failed calls recorded with only the result's sha256 and length, 96 of 98 runs with tools reaching the round limit with nothing saying so, 7 "deliveries" that were only tool-call markup typed in the tool-less final turn, and research fetches refused by the host allowlist without a recorded reason. Now a failed call's observation carries `error`, the first 300 characters of the error text the backend produced or received, secret-looking lines redacted; the run's evidence carries `rounds_used`, `rounds_max` and `rounds_exhausted`, counted by the loop; a final answer that is only a tool call written as text (`contracts.tool_calls.written_as_text`) is taken like an empty answer and never delivered: the task is retried once, then blocked with "the model's last answer was a tool call written as text; the tool budget had run out"; and a research fetch the allowlist refused tells the model `Refused: host not allowed` with why and records `refused: host not allowed` on its observation.
* **A final answer that is only a tool call written as text is retried once before the task is blocked (issue #766).** The first time, the worker queues the task again through the transient-failure path (`intake.requeue_after_transient_failure`, a `retried` event saying "Final answer was a tool call written as text, queued again with a fresh tool budget"), and the next attempt opens a new toolbox with its full tool budget; only a second such answer blocks the task, its reason saying it happened again after one retry. Both stay on the task's events.
