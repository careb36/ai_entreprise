* **The PO and the Architect read the project while they write, and the plan from a specification checks what is already done (issue #766).** The PO writing a specification and the Architect writing or revising an architecture get the read-only workspace tools (list, read, search, find_file, read-only Git and a document's text when announced) beside their research tools, as their step allows (R and S), for at most `PLANNING_TOOL_ROUNDS` and `ARCHITECT_TOOL_ROUNDS` rounds; they never edit or run anything. Each round is an audit turn (`spec_author_read`, `arch_author_read`) that keeps the tool calls as observations. The plan from an approved specification reads the project like the plan from a prompt and is asked what is already done: its claim (`already_done_claim`) stays apart from what the platform observed of its reads (`already_done_observed`), and a plan whose every part is claimed done is one QA task that verifies the specification with the tests. Without a daemon or a project path, all three are unchanged.
