* **A company's own standards, imported from its repository, activated by a second person, and time-boxed exceptions (issue #700, first part).** A company writes checks the factory runs without a model in `.fabrique/standards.toml` (TOML, `tomllib`; per-folder rules as `[folders."<path>"]` tables), each of a kind fixed in code: `command`, `forbid_pattern`, `require_together`, `max_lines`, `forbid_path` (`services/contracts/company_standards.py`, design in `docs/design/COMPANY_STANDARDS.md`). A Manager imports it (`POST /v1/companies/{id}/standards/import`): the daemon reads the file at the head of the default branch, never a task branch or the checkout (new subject `workspace.git.read_at`, `vscode-daemon/git_read_at.py`, protocol §5.5), the backend hashes the bytes and every guard's files (whole folders, `exclude` globs, symbolic links refused), validates the file with every refusal named (a catalogue `STD-` id anywhere refuses it whole: a company only adds; a command that fetches, escalates or leaks is refused; a pattern runs on RE2 through the pinned `google-re2` binding, never on Python's `re`, OWASP ReDoS / CWE-1333) and dry-runs the in-backend kinds on that commit (`fails_on_source`). The draft is activated only by a signed-in Owner who did not import it (four-eyes whatever the SoD mode, ISO/IEC 27001:2022 A.5.3; the only Owner may activate their own import with a reason, flagged in the access review until a second Owner confirms it), never with a refusal, never with a `command` standard unless commands run in the `container` or `bwrap` sandbox (fail closed, OWASP ASVS 4.0.3 V1.4); `change_standards` joins `ALWAYS_ESCALATE`, and every import, activation, deactivation and rejection is audited with both sha256 values. Exceptions are the only way around a standard (ISO/IEC 27001:2022 A.5.36): an Owner requests one with a reason, a compensating control and at most 90 days, a second Owner approves it, it lapses on its own and the access review lists it (`/v1/companies/{id}/standards/exceptions`). Migration `0057` adds `company_standard_sets` and `company_standard_exceptions`. The Verifier's `company_standards` check on deliveries comes in the next part.
