Added

* **First tools for documenting a whole project (issue #766).** `workspace__git` gains `blame`: one path's line range (at most 200 lines) as groups of lines with the commit, date and subject that last changed them, never an author's or committer's name or e-mail (`vscode-daemon/git_view.py`, announced as the `blame` feature, PROTOCOL.md §5.6). `workspace__read_document` returns the text of a DOCX in the project through the daemon, bounded and redacted, with the sha256 of the file's bytes recorded (`workspace.read` with `extract: "text"`, `vscode-daemon/document_text.py`, PROTOCOL.md §5.7); PDF is refused for now, as the daemon has no PDF reader. The Verifier checks a delivery that changes Markdown under a docs folder or a README: `docs_links` (relative links and anchors resolve in the delivered tree) and `docs_code_paths` (paths cited in inline code exist), against the daemon's listing and read-back texts; a broken one refutes and the gate sends the delivery back (`services/evidence/doc_links.py`). A documentation task's edit tools write only documentation paths (`services/tools/docs_write_policy.py`); other paths are refused with a reply.
