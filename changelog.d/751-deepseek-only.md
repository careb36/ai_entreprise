Changed

* **DeepSeek only: no other configuration stops the work (issue #751).** With `DEEPSEEK_API_KEY` alone, a request DeepSeek answers with 429, 5xx or an empty answer now moves to DeepSeek's other model (Pro to Flash, Flash to Pro) instead of skipping DeepSeek, and moves to another provider only when the operator names it in the new `LLM_FALLBACK_PROVIDERS` (default empty), so a key configured for one role no longer makes that provider a processor of every other role's prompts. Embeddings default to the local vector (`EMBEDDING_PROVIDER=local`, no key and no outside call; DeepSeek has no embeddings endpoint); Gemini embeds only when chosen with `EMBEDDING_PROVIDER=gemini`, its 768 values padded to the 1536 of `vector_memory.embedding`, which they did not fit before. The backend and the proxy log the effective capability set at startup (names and reasons, never a value), `/health/deep` gains a `capabilities` section (the backend's beside the proxy's `llm.*`; it never changes the status), and the Models page shows it as Capabilities. The audit is `docs/design/DEEPSEEK_ONLY.md`; a local semantic embedding model is #755, the bench's real-model job requiring a Gemini key is #756.
