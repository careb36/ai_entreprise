Changed

* **Agent code runs in a container by default, in an image built for the project (issue #766).** `DELIVERY_SANDBOX` now defaults to `container` (it was `host`: agent-written code ran on the daemon's computer), and `DELIVERY_SANDBOX_IMAGE` to empty. With it empty the daemon builds the project's own image from its stacks, read from marker files (`pyproject.toml`, `package.json`, `go.mod`…) at the root and one folder down, from fixed templates only (Python with Poetry and pytest, Node with npm, Go, git), tags it `fabrique-stack:<sha256 prefix>` and reuses it (`vscode-daemon/stack_image.py`, the new `workspace.sandbox.image`). The loop has it built before a delivery's commands (`STACK_IMAGE_BUILD_TIMEOUT_SECONDS`, 1900) and records `evidence["stack_image"]`; a run whose image cannot be built fails with the reason. Every `workspace.execute` reply carries `duration_ms`, kept on `test_run`. A project's own `.fabrique/sandbox.Dockerfile` is not read yet, because agents write the worktree.

  **Upgrading:** the daemon's machine needs Docker or Podman. A `.env` that sets `DELIVERY_SANDBOX=host` keeps the host and needs the `host_sandbox` acknowledgement; one that sets `DELIVERY_SANDBOX_IMAGE` keeps that image. The first delivery of a project waits for its image to build (a few minutes, once).
