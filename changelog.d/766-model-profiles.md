Added

* **A model's profile sets the Developer's limits (issue #766).** `services/models/model_profile.py` builds each model's profile from the operator's overrides (`MODEL_PROFILES`, a JSON object by model name), the models.dev catalogue and the settings, after the OpenHands SDK's capabilities registry and its `[llm.<name>]` profiles: the context, output limit and tool calling, and the Developer's tool rounds, tool-result budget and answer cap (`DEVELOPER_MAX_OUTPUT_TOKENS`, new, `0` by default: the provider's own). The run's evidence keeps the profile with the source of each field; the limits stay under fixed ceilings and a malformed override is ignored. With no override nothing changes. `LLM_UPSTREAM_TIMEOUT_SECONDS`, `LLM_THINKING` and `LLM_THINKING_RESERVE_TOKENS` are settings now, defined once, and a value that is not a positive number keeps the default as before.
