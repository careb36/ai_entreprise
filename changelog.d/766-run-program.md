* **Agents run the programs a project declares, and the platform reads their metrics (issue #766).** First slice of `docs/design/project-programs-and-screenshots.md`, now approved with the owner's eight decisions. A Manager declares entry points in the stack profile's new `programs` field (`backend/app/services/contracts/programs.py`): a committed entry file, fixed plain argv words, typed and bounded parameters, the metrics' line prefix or file, a tolerance, a precision and thresholds, checked on save (`backend/app/services/workspace/stack_roots.py`) and at each call. The new tool `workspace__run_program` (`backend/app/services/tools/program_runs.py`), family X, is withheld with the reason in the run's existing `tools_offered` when nothing is declared, the company's sandbox is not `container` or a daemon does not announce the new `program` feature of `workspace.execute`; it refuses free text, out-of-bounds values and an entry file changed on disk, and caps runs per task attempt (`PROGRAM_RUNS_PER_TASK`, `PROGRAM_EVAL_RUNS_PER_TASK`). The daemon's new `vscode-daemon/program_run.py` (PROTOCOL.md §5.12) refuses `host` and `bwrap`, turns the network off, mounts the worktree read-only, gives a capped per-run artifacts folder outside the worktree with a free-space floor and a size watch that kills the run, caps time, CPU, memory and processes by `FABRIQUE_PROGRAM_MAX_*`, and replies a manifest with each artifact's sha256 read back. The backend parses metrics only from the stdout and metrics file it hashed, never stderr (`backend/app/services/contracts/program_metrics.py`), and records them as `observed_metrics` with provenance `program_output` or `committed_evaluator`; an agent's `claimed-metric:` lines stay in the run's claims. The Verifier's new `metric_matches` and `metric_threshold` checks (`backend/app/services/evidence/metric_matches.py`) refute a claim outside the declared tolerance and accept a quality metric only from a `committed_evaluator` at the low and medium tiers; a refutation sends the delivery back. The project settings page keeps stored programs when it saves. `docs/design/owner-actions.md` records the owner's answers on the SSO step-up and on which sprints a land waits for.
