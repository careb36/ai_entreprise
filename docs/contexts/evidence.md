# The evidence context

Part of the project's guidance for agents; the index is [`CLAUDE.md`](../../CLAUDE.md). Read this document before changing code in `backend/app/services/evidence/`.

- **Folder:** `backend/app/services/evidence/`
- **Responsibility:** Judging a run from what was observed: the Verifier's checks and verdict, the risk tier, the quality standards check, acceptance tests per criterion, the context-read check, the application and browser checks as read from the daemon's reply, SecOps scans, the gate before QA, the changes of a run and the ingestion of AgentRun records. It reads the daemon's reply as data from contracts; it never calls the daemon, the loop, the tools or a producer.
- **May import:** [contracts](contracts.md), [platform](platform.md) (`docs/architecture/contexts.json`, checked by `scripts/check_architecture.py`).
- **Modules:** `acceptance`, `agent_run_service`, `app_check`, `browser_smoke`, `console_run`, `context_read`, `criteria_tests`, `delivery_gate`, `governance`, `grounding`, `imports`, `manifests`, `review_changes`, `risk`, `secops_checks`, `signatures`, `sources`, `standards`, `verification`.

## Components

### What a run changed

**`backend/app/services/evidence/review_changes.py`** — What a run changed, the way a code review shows it: `GET /v1/agent_runs/{id}/changes` reads the daemon's per-file diffs from the latest verification whose evidence carries them, or a pull request's diff (the artifact of a GitHub-ingested run), or, with neither, a diff the producer sent as its artifact (labelled `artifact`), with one `git diff` parser; the files the producer only declared come back apart (`declared_not_observed`), never as changes. The run page's **Files changed** tab (`components/ReviewChanges.tsx`, `lib/patch.ts`) renders it like a pull request.

### The quality standards

**`backend/app/services/evidence/standards.py`** — The quality standards every project is held to: a fixed catalogue by discipline (`STD-ARCH-1` … `STD-PO-1`, with `STD-OPS-2` for DevOps, `STD-DATA-1` for data and migrations and `STD-UX-1` for accessibility, `docs/STANDARDS.md`) that no model, request or procedure edits; `for_role` reads a role through `roles.canonical` and binds the specialised developers to every Developer standard too (`DISCIPLINES`), never fewer. `prompt_section(role)` goes into every prompt by role (the task prompt before the company's procedures, QA's review, the PO's draft and plan, the Architect's design); a procedure adds to the standards, never relaxes them. `check_delivery` is the Verifier's `standards` check over the files a deliverable declares: a secret-looking value (keys, tokens, private keys, a password assigned in code; placeholders and `os.environ` references are not) refutes the delivery and the gate sends it back (`standards violated`); code without a test, a `TODO`/`FIXME` left behind and an unpinned dependency (`requirements*.txt`, `package.json`) are findings the reviewer sees. `missing_quality_areas` gives the specification check its `quality_area_missing` warnings. `GET /v1/standards` serves the catalogue; `tests/test_standards.py` keeps the document in step with it.

### The grounding check

**`backend/app/services/evidence/grounding.py`** / **`manifests.py`** / **`imports.py`** — The Verifier's `grounded` check (issue #444): the packages, exact versions and imports a delivery names must exist. `manifests.dependencies_in` reads the delivered manifests (`requirements*.txt`, `pyproject.toml` PEP 621 and Poetry, `package.json`, `go.mod`, `Cargo.toml`; exact pins only, path/Git/URL dependencies left out), and an edit's fragment is read by its sections. `imports.imports_in` reads Python, JavaScript/TypeScript, Go and Rust imports; `imports.ProjectIndex` resolves the project's own modules against the paths the daemon reported (`project_files`, capped at `PROJECT_INDEX_MAX` and marked `truncated`), and `imports.audit` separates an unresolved project import from a third-party one its manifest does not declare. A package no registry has or an exact version the registry lacks refutes the delivery (`grounded` -> `invented dependency or import` in the gate); a registry that was not asked, an exact version no answer addressed, an unresolved import when the listing is truncated, an unresolved import from a test file (QA writes its acceptance tests before the module they name, `criteria_tests.is_test_file`), and an undeclared third-party import when the manifest was only edited are findings. The registry answers are observations recorded at delivery time (`services/tools/registry_lookup.py`, `registry_lookups` on the evidence) or by the run's own `research__package` calls; verification never reaches the network. **Symbols** (`signatures.py`): every call a delivered Python file makes to a project function or class is compared with its signature, and a mismatch is a finding in the check's details (`signature_mismatches`: file, line, callee, what was passed, the signature rendered as `f(a, b=…, *, c)`, and its source, `daemon` with the file's sha256 or `delivered`), never a refutation: the verdict and the gate do not change, since the map is partial and Python resolves names at run time. The callee is a name imported from a project file (`from a.b import f`, `a.b.f` after `import a.b`, `m.f` after `import a.b as m`, a relative import; the file found through `ProjectIndex`, one file or none, a standard-library name only at that exact path) or a module-level definition of a delivered file. Compared: the positional count against the signature's bounds, each keyword against the parameter names (unless `**kwargs`; a positional-only one or one given twice too), and the required parameters left unfilled. Skipped: a call unpacking `*x` or `**x`, a name bound more than once anywhere in the file (rebound, a parameter, a local), and a signature reported `unknown` (decorated, a constructor that is not the class's own `__init__`, a name bound twice in its module) or `missing` (a star import may provide it). The signatures of files the delivery did not write are observations the backend recorded at delivery time (`services/tools/signature_lookup.py`, `signatures` on the evidence: what was asked, the daemon's reply with each file's sha256, or `observed: false` and the reason when the daemon could not be asked, an older daemon included); a delivered file's own are read from the delivered text; verification never asks the daemon, and a model's claim is never read. The details say whether signatures were observed (`signatures_observed`) and how many calls were compared; calls to project code that could not be compared are named in the observation. Python only: JavaScript accepts any number of arguments, so a count proves nothing there, and Go and Rust are out of scope. A delivery queued for an offline daemon records the signatures as not observed. The idea is Gorilla's APIBench (invented API calls) and the repository map; no code taken. `tests/test_grounding.py` covers the parsers, the resolution and the outcomes, `tests/test_grounding_signatures.py` the symbols.
