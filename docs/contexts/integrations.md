# The integrations context

Part of the project's guidance for agents; the index is [`CLAUDE.md`](../../CLAUDE.md). Read this document before changing code in `backend/app/services/integrations/`.

- **Folder:** `backend/app/services/integrations/`
- **Responsibility:** Telling the outside world: the company's notification webhook and the outbox processor that posts it. It listens to changes of the task record and the evidence; nothing below it imports it.
- **May import:** [contracts](contracts.md), [platform](platform.md), [tasks](tasks.md), [evidence](evidence.md) (`docs/architecture/contexts.json`, checked by `scripts/check_architecture.py`).
- **Modules:** `chat_approvals`, `chat_client`, `chat_connections`, `chat_links`, `chat_messages`, `chat_signatures`, `outbox_service`, `webhook_client`, `webhooks`.
- **HTTP adapters** (`http_adapters` in `docs/architecture/contexts.json`, checked by `scripts/check_architecture.py`, issue #511): `webhook_client` (the signed POST, raising `WebhookPostError`; `webhooks.deliver` calls it); `chat_client` (Slack's Web API at the fixed `https://slack.com/api/` for four named methods, and a POST to a Teams incoming webhook URL already checked; raises `ChatPostError` with Slack's error code or the transport exception's type, never the Teams URL; `chat_approvals.deliver` and `chat_connections.test` call it). Only these modules of the context may import an HTTP library; each returns data and raises named errors, and the rest of the context calls it.

## Components

### The notification webhook

**`backend/app/services/integrations/webhooks.py`** / **`routers/webhooks.py`** — The company's notification webhook (issue #357): one per company (`CompanyWebhook`: an https URL, a Fernet-encrypted secret never returned, the events among `task_done`, `task_blocked`, `sprint_closed`, `run_refuted`, on or off; `GET`/`PUT`/`DELETE /v1/companies/{id}/webhook`, Viewer / Manager, `POST .../webhook/ping`). A `before_flush` listener over every session (`install`, called by `main.py`) sees a task's status change to done or blocked (with `block_reason` and `waits_for_a_person`), a sprint's to completed and a new refuted `Verification`, and adds an `OutboxEvent` (`webhook_post`) in the same transaction, so a change that rolls back sends nothing and no caller has to know about webhooks. The outbox processor posts it (`deliver`) with `X-Fabrique-Event`, `X-Fabrique-Delivery` and `X-Fabrique-Signature-256: sha256=<HMAC of the body>` (GitHub's shape); a non-2xx answer or an error is recorded on the webhook (`last_status`, `last_error`) and retried with backoff (the outbox waits `retry_count² × 10 s` between attempts, five at most). A webhook that is down never holds up a sprint. The URL's host must resolve to public addresses unless `WEBHOOK_ALLOW_PRIVATE_HOSTS`.

### Approvals in Slack and Teams

A chat decision is held to segregation of duties like the web's, since it calls the same `submit_review` (issue #543): the person who started the sprint is refused in chat with the reason, the claimed message is released for another person, and `sod_refused` and `chat_approval_refused` are audited.

**`backend/app/services/integrations/chat_*.py`** / **`routers/chat_approvals.py`**, **`routers/chat_interactions.py`** — Approving from chat (issue #512, phase 4; design and threat model in [`docs/design/CHAT_APPROVALS.md`](../design/CHAT_APPROVALS.md); `models/chat.py`, migration `0023`). One connection per company and provider (`ChatConnection`, `chat_connections`): Slack (workspace id, channel id, bot token, signing secret) or Teams (tenant id, incoming webhook URL on a Microsoft host, outgoing webhook key), both credentials Fernet-encrypted and never returned (`describe` says `has_*`), managed only by a signed-in Owner (`GET /v1/companies/{id}/chat`, `PUT`/`DELETE …/chat/{provider}`, `POST …/chat/{provider}/test`; API tokens refused), every change audited by field name. The approval point wired is the **risk hold**: a `before_flush` listener (`chat_approvals.install`, called by `main.py`) sees a new `risk_hold` task event and queues `chat_approval_post` in the same transaction for each enabled connection; the outbox processor (`deliver`) reads the point again from the record (`approval_point`: still held, the latest run and version, the Verifier's verdict and the checks that did not pass, links to `/evidence/{run}` and the task; never the run's claims) and posts Block Kit buttons (Slack) or an Adaptive Card with a short code (Teams), recording a `ChatApprovalMessage` with the hold event's chain hash and the run's version. Inbound (`routers/chat_interactions.py`, public, `CHAT_RATE_LIMIT`, 64 KiB): `POST /v1/integrations/slack/{public_id}/interactions` (buttons and the `/fabrique link CODE` command) and `POST /v1/integrations/teams/{public_id}/messages` (an outgoing webhook: `approve CODE`, `sendback CODE <reason>`, `link CODE`). In order: the URL's connection; the signature (`chat_signatures`: Slack v0 HMAC over `v0:{ts}:{body}` with the timestamp within 300 s, Teams `Authorization: HMAC` over the body with the activity's own timestamp within 300 s; `hmac.compare_digest`); the interaction id stored once (`ChatInteraction`, unique: a replay does nothing); the workspace or tenant; the chat user's link (`ChatIdentity`, made by a one-time code the person asked for while signed in, `chat_links`; never by email); `require_company_role(..., "Manager")` with that user, as the web review; the message still matching the record and taken with a conditional update (`chat_approvals.claim`). Then `services/loop/run_review.submit_review` decides with `via` (its `run_review_<event>` audit row carries `via` and `user_id`), `chat_approval_<outcome>` names the person, the platform and the chat user, and `chat_approval_update` edits the Slack message (Teams answers in the thread). A refusal changes nothing, is audited as `chat_approval_refused` and is shown in chat (Slack: `chat_ephemeral` through the outbox; Teams: the reply). Each member links or unlinks their own account (`GET /v1/companies/{id}/chat/links`, `POST …/links/{provider}/code`, `DELETE …/links/{provider}`); the page is `/company/chat` (`pages/ChatApprovals.tsx`, `components/ChatConnectionForm.tsx`).
