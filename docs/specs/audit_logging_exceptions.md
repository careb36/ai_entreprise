# Specification: Audit Logging for Agent Exceptions

## Overview
Enhance the AI verification audit logs to specifically track LLM timeout durations, retry counts, and self-correction loop iterations. This provides better data for future retro analysis and ensures dependable, audit-proof records for code generated by autonomous agents.

## Requirements
1. **Timeout Duration Tracking**: Log the duration (in milliseconds) of LLM API timeouts.
2. **Retry Tracking**: Log the number of retry attempts made during an execution cycle.
3. **Self-Correction Tracking**: Log the number of self-correction iterations the agent performed.
4. **Data Separation**: Maintain strict separation between what the agent claims it did and what the system observed.

## Acceptance Criteria
- [ ] The `AgentAuditLog` schema includes `timeout_duration_ms`, `retry_count`, and `self_correction_iterations`.
- [ ] Simulated timeouts successfully record the timeout duration and retry counts in the PostgreSQL database.
- [ ] Automated tests verify the schema properties and ensure performance and reliability constraints are met.
- [ ] Claims (agent reported metrics) and observations (system recorded metrics) are separated per STD-AUD-1.

## Quality Attributes
- **PERF-1**: Database insert operations for a single audit log entry must complete in under 50 milliseconds.
- **REL-1**: The logging mechanism must capture 100% of exception events during simulated network timeouts with 0 data loss.
- **SEC-1**: Audit logs must not store any sensitive API keys or tokens (0 secrets exposed).
- **ACC-1**: The JSON serialization of the audit logs must be 100% compatible with standard log aggregators (e.g., Datadog, ELK) to ensure accessibility for visually impaired developers using screen-reader-friendly log viewers.
